# 운영 테스트 대본 (실기기)

배포한 서버에서 독서모임 한 팀(3~5명)이 실제 휴대폰으로 한두 판을 진행하며 **게임 경험**과 **기기 문제**를 함께 확인하는 60분 세션 대본입니다. 개발 계획 §10(W7~W8 소규모 운영)과 §11 지표, 기획안 9장 "첫 테스트에서 관찰할 것"을 기준으로 했습니다.

## 0. 이번 세션이 답할 질문

| # | 질문 | 확인 방법 |
|---|---|---|
| Q1 | 설명 없이 15분 안에 한 판을 끝내는가 | 1판 시작~성운 저장 시각 (관찰 기록지) |
| Q2 | 문장 작성이 한 사람에게 몰리지 않는가 | 운영 지표의 기여 균형(지니), 관찰 |
| Q3 | 휴대폰에서 끊기거나 새로고침해도 이어서 할 수 있는가 | §5 의도적 개입 A~D |
| Q4 | 신고와 방장 숨김이 실제로 동작하는가 | §5 의도적 개입 E |
| Q5 | 다시 하고 싶은 이유가 경쟁이 아니라 연결인가 | §6 회고 인터뷰 |
| Q6 | 문학적 표현에 익숙하지 않은 사람도 선택지와 짧은 답으로 기여감을 느끼는가 | 관찰 + 인터뷰 |

## 1. 역할

| 역할 | 인원 | 하는 일 |
|---|---|---|
| 진행자 | 1 | 대본을 읽고 시간을 지키며, §5 개입을 지시한다. **게임 방법은 설명하지 않는다** |
| 관찰자 | 1~2 | 관찰 기록지(§7)에 시각과 함께 적는다. 참여자에게 말을 걸지 않는다 |
| 참여자 | 3~5 | 자기 휴대폰으로 참여. 이 중 1명은 방장, 1명은 §5-E의 협조자 |

진행자와 관찰자는 게임에 참여하지 않습니다. 인원이 적으면 진행자가 관찰을 겸해도 되지만 기록은 반드시 남깁니다.

## 2. 사전 준비

### 하루 전

- [ ] 배포 서버 `/api/health`가 `{"ok":true,"activeGames":0}`으로 응답한다
- [ ] `ACCESS_CODE`가 설정돼 있고, 진행자가 코드를 안다
- [ ] 진행자 휴대폰으로 방 만들기 → 다른 기기로 초대 링크 입장까지 한 번 해 본다
- [ ] 세션 시간에 배포가 겹치지 않게 자동 배포를 멈추거나 일정을 공유한다 (`AUTO_DEPLOY`를 잠시 `false`로)
- [ ] 참여자에게 녹화·기록 동의를 받는다 (§8)
- [ ] 관찰 기록지와 기기 점검표를 인쇄하거나 공유 문서로 준비한다

### 기기 구성

참여자 기기가 아래 칸을 최대한 채우도록 미리 물어보고 배정합니다. 빈 칸은 진행팀 기기로 채웁니다.

| 칸 | 기기 | 브라우저 | 네트워크 | 배정 |
|---|---|---|---|---|
| D1 | iPhone (iOS 최신) | Safari | Wi-Fi | |
| D2 | iPhone (iOS 한 단계 이전) 또는 작은 화면(SE) | Safari | LTE/5G | |
| D3 | 중저가 안드로이드 (RAM 4GB 안팎) | Chrome | Wi-Fi | |
| D4 | 삼성 갤럭시 | 삼성 인터넷 | LTE/5G | |
| D5 | 노트북 또는 태블릿 (방장 역할 추천) | Chrome 또는 Safari | Wi-Fi | |

- 배터리 50% 이상, 저전력 모드 끄기 (저전력 모드에서의 동작은 따로 한 번 확인)
- 화면 녹화가 가능하면 켜 둔다 (iOS 제어 센터 화면 기록 / 안드로이드 화면 녹화)

### 30분 전

- [ ] 진행자가 새 방을 만들지 않고 기다린다 (방장은 참여자가 맡는다)
- [ ] 관찰 기록지 첫 줄에 날짜, 팀 이름, 인원, 기기 배정을 적는다
- [ ] 협조자(§5-E)에게 따로 역할을 알려 준다

## 4. 진행자 대본

### 4-1. 소개 (그대로 읽기)

> 오늘은 두 개의 주머니에서 뽑은 물건으로 함께 하나의 세계를 만드는 게임을 해 볼 거예요. 아직 만들고 있는 단계라 여러분이 헤매는 지점이 저희에게 가장 중요한 정보입니다. 게임 방법은 일부러 설명하지 않을게요. 화면만 보고 해 보시고, 막히면 막힌다고 소리 내어 말해 주세요. 정답이나 점수는 없어요. 중간에 제가 "휴대폰을 잠깐 꺼 주세요" 같은 부탁을 드릴 텐데, 기기 문제를 확인하려는 거라 그대로 따라 주시면 됩니다.

### 4-2. 접속

> (방장에게) 첫 화면에서 '새 세계 발견'을 눌러 방을 만들고, 대기실의 '초대 링크 보내기'로 모두에게 링크를 보내 주세요.

- 관찰: 초대 링크 공유 방식(카카오톡, 문자, 에어드롭), 링크로 들어왔을 때 접근 코드 화면이 뜨지 않는지, 닉네임 입력에서 망설이는지

### 4-3. 진행 중 원칙

- 질문을 받으면 되묻기: "화면에서는 뭘 하라고 하는 것 같아요?"
- 30초 넘게 모두 멈춰 있을 때만 한 문장 힌트: "화면 위쪽에 지금 누구 차례인지 보여요"
- 힌트를 줬다면 관찰 기록지에 시각과 내용을 적는다 (Q1 판단에 반영)
- 기술 오류가 나면 게임을 멈추지 말고 시각과 화면을 기록한 뒤 §5의 복구 방법을 안내한다

## 5. 의도적 개입 (기기·연결 시나리오)

개입은 진행자가 해당 참여자에게만 조용히 부탁합니다. 각 항목의 **기대 동작**과 다르면 관찰 기록지 '문제' 칸에 적습니다.

| # | 시점 | 누가 | 할 일 | 기대 동작 |
|---|---|---|---|---|
| A | 1판 2라운드, 답을 쓰는 중 | D1 | 문장을 반쯤 쓴 상태에서 화면을 10초 끄고 다시 켠다 | 쓰던 문장이 남아 있고 같은 라운드에 이어서 제출된다. 다른 사람 화면은 "쓰는 중…"으로 기다린다 |
| B | 1판 2라운드 | D2 | Wi-Fi를 끄고 LTE로 바꾼다 (또는 반대) | 화면 위에 "연결이 잠시 끊겼어요" 안내가 잠깐 뜨고 저절로 돌아온다 |
| C | 1판 3라운드 | D3 | 브라우저 탭을 완전히 닫고, 받은 초대 링크로 다시 들어온다 | 닉네임을 다시 묻지 않거나 같은 이름으로 같은 자리에 돌아온다. 지난 조각이 그대로 보인다 |
| C2 | C 직후 | D3 | 30초 넘게 돌아오지 않는다 | 다른 사람이 모두 답했다면 20초 뒤 남은 사람만으로 라운드가 넘어간다(쓰던 초안이 있으면 그 문장으로 제출). 돌아오면 다음 라운드부터 참여 |
| D | 2판 탐사 중 | 방장 | 브라우저를 닫고 40초 기다린다 | 30초 뒤 다른 사람이 방장이 된다(대기실·연결 화면의 '방장' 표시와 '지금 마감하기' 버튼으로 확인) |
| E | 1판 4라운드 | 협조자 | 미리 정한 문장을 쓴다: "이 우산은 정말 닥쳐 하고 싶을 때 쓴다" | 보내기 전에 "이 표현, 괜찮을까요?" 확인이 뜬다. 그대로 보내면 문장에 '확인 필요' 표시. 다른 참여자가 ⋯ → 신고하기 → 방장에게 알림 → 방장이 숨기기 → 모두의 화면에서 "방장이 숨긴 문장이에요" |
| F | 1판 완성 화면 | D1, D3, D4 | '이미지로 내보내기'를 누른다 | iOS: 이미지가 저장되거나 공유 시트가 뜬다. 안드로이드: 다운로드 폴더에 PNG. 파일 이름이 세계 이름인지, 글꼴이 깨지지 않는지 확인 |
| G | 2판 아무 때나 | D2 | 시스템 설정에서 '동작 줄이기'(iOS) / '애니메이션 제거'(안드로이드)를 켠다 | 떠다니는 파우치·번지는 전환이 사라지고 바로 바뀐다 |

> 협조자 문장(E)은 금칙어 확인 기능을 시험하려는 것입니다. 다른 참여자에게 불쾌감을 주지 않도록 세션 시작 때 "테스트용 문장이 하나 나올 수 있다"고 미리 알려 둡니다.

## 6. 회고 인터뷰 (10분)

점수를 묻기 전에 장면을 묻습니다. 한 사람이 길게 답하면 다른 사람에게도 같은 질문을 돌립니다.

1. 처음 두 토큰이 떠올랐을 때 무슨 생각이 들었어요?
2. 가장 오래 멈춰 있었던 순간은 언제였어요? 그때 무엇을 기다리고 있었어요?
3. 다른 사람이 쓴 설정을 이어 쓴 적이 있어요? 바꾸고 싶었던 적은요?
4. 완성된 세계에서 다시 읽고 싶은 문장이 있다면 어느 것이고, 왜요?
5. (선택지로 답한 사람에게) 선택지로 답했을 때도 내가 세계를 만들었다는 느낌이 있었어요?
6. 별(놀라움·연결·여운)을 보낼 때 어떤 기준으로 골랐어요?
7. 다음 모임에서 또 하자고 하면 하고 싶어요? 그 이유는 무엇인가요?
8. 휴대폰에서 불편했던 점이 있었어요? (글자 크기, 키보드가 버튼을 가림, 느림 등)

마지막에 재미를 5점 척도로 묻되, 다른 답보다 가볍게 다룹니다.

## 8. 동의와 개인정보

- 닉네임은 실명이 아니어도 된다고 안내한다
- 화면 녹화와 관찰 기록은 내부 개선에만 쓰고, 세션 뒤 4주 안에 지운다고 알린다
- 게임에서 쓴 문장은 서버에 저장되며, 원하면 해당 세계 기록을 지울 수 있다고 알린다 (요청 시 `/data/worlds.json`에서 수동 삭제)
- 동의하지 않는 사람은 녹화를 끄고 관찰 기록에서 이름 대신 기기 칸만 적는다

## 9. 세션이 끝난 뒤

1. **데이터 백업** (`docs/DEPLOYMENT.md` 운영 절)
2. **지표 확인**: `fly ssh console -C "sh -c 'cd /app/apps/server && DATA_DIR=/data pnpm metrics'"`. 완주율, 한 판 중앙값, 기여 균형, 연결 행동, 선택지 비율, 신고·숨김 수를 결과 요약에 옮긴다
3. **신고 기록 확인**: `/data/reports.jsonl`에 협조자 문장 신고가 1건 들어왔는지
4. **문제 기록 정리**: 아래 양식으로 하나씩 적고 심각도를 매긴다

```
[문제 번호]
기기 칸 / 기기 / OS / 브라우저:
단계: (대기실 · 추첨 · 명명 · 탐사 · 연결 · 기록 · 성운)
무엇을 했나:
기대한 것:
실제로 일어난 것:
다시 일어나는가: (항상 / 가끔 / 한 번)
화면 녹화 위치 · 시각:
심각도: 진행 불가 / 불편 / 사소함
```

5. **결과 요약 한 장**: §0의 Q1~Q6 각각에 '예 / 아니오 / 판단 보류'와 근거 한 줄, 다음 세션 전에 고칠 것 상위 3개

|---|---|
| 1판이 20분을 넘는다 | 기본 라운드를 4회로, 답변 시간을 90초로 낮춰 다시 본다 |
| 힌트가 3번 넘게 필요했다 | 힌트가 필요했던 화면의 안내 문구를 고친다 |
| 같은 사람이 매 라운드 먼저 쓴다 / 지니 0.3 이상 | 고요한 탐사 기본값, 선택지 노출 시점을 검토한다 |
| 재접속 시나리오에서 ✕가 하나라도 나왔다 | 다음 세션 전에 반드시 고친다 |
| "또 하고 싶다"의 이유가 기발함·승부 위주다 | 별 보내기와 완성 화면의 강조 방식을 검토한다 |
