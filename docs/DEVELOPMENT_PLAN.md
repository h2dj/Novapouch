## 0. 한눈에 보기

| 항목 | 결정 |
|---|---|

## 3. 게임 규칙의 상태 기계

서버가 방 단위로 하나의 상태 기계를 보유하고, 모든 전이는 서버에서만 일어난다. 클라이언트는 `room:snapshot`을 받아 그리기만 한다.

```
LOBBY ──(방장 시작, 2명 이상)──▶ DRAW ──(A·B 공개)──▶ IMAGINE(5s)
  ▲                                  ▲ 다시 흔들기(1회, 속성만)      │
  │                                                                   ▼
  │                                                         NAMING(60s, 첫 발견자)
  │                                                                   │
  │                               ┌──────────── EXPLORE(라운드 n/N) ◀┘
  │                               │   질문 선택(차례) → 답변(동시, 제한시간)
  │                               │   → 공개(고요한 탐사면 전원 제출 후) → 다음 라운드
  │                               ▼
  │                        CONNECT: 조각 후보 투표 → 규칙 3 + 장소/주민/사건 확정
  │                               ▼
  │                        RECORD: 세계 이름 제안·투표, 공개 범위 합의, 별 보내기
  │                               ▼
  └──────(새 조합으로 다시)──── DONE: 성운 저장, 이미지 내보내기
```

규칙 구현 원칙
- 상태 전이 로직은 `packages/game-core`의 **순수 함수** `reduce(state, action) → state`로 작성한다. 서버와 테스트가 같은 코드를 쓴다.
- 타이머는 서버 시계 기준 `deadlineAt`만 내려보내고 클라이언트는 표시만 한다.
- 이탈자가 있어도 진행이 멈추지 않게 한다: 차례인 사람이 30초 무응답이면 다음 사람에게 질문 선택권이 넘어간다. 답변은 "건너뜀"으로 기록한다.
- 방장이 나가면 가장 먼저 입장한 사람이 방장이 된다.

## 4. 시스템 아키텍처

```
[모바일/데스크톱 브라우저]
  React SPA (Vite)  ── HTTPS REST ──▶  Fastify API ──▶ PostgreSQL (Prisma)
        │                                  │
        └──── WebSocket (Socket.IO) ──────▶ Room Manager (방별 상태 기계, 메모리)
                                           │  └ 상태 변경마다 이벤트 로그 append → DB
                                           └ 금칙어 필터 / 신고 처리
```

### 4.1 저장소 구조 (pnpm 모노레포)

```
apps/
  web/          React + Vite + TS, 화면·디자인 시스템
  server/       Fastify + Socket.IO, 방 관리, REST
packages/
  game-core/    상태 기계, 규칙, 타입 (서버·클라 공용, 의존성 없음)
  content/      토큰·질문 카드 JSON + 스키마 검증(zod)
  ui-tokens/    색·타이포·간격·모션 디자인 토큰
docs/
```

### 4.2 기술 선택 이유

| 영역 | 선택 | 이유 |
|---|---|---|
| 프런트 | React 18 + Vite + TS | 기획안 권장 스택. 생태계와 이미지 내보내기 라이브러리가 풍부함 |
| 상태 | Zustand(클라) + 서버 스냅샷 | 게임 상태는 서버가 원본이고 클라이언트 상태는 UI 전용 |
| 실시간 | Socket.IO | 모바일 네트워크 전환 시 자동 재연결, room 개념 내장 |
| 서버 | Fastify | 가볍고 TS 친화적. REST와 WS를 한 프로세스에 둠 |
| DB | PostgreSQL + Prisma | 기획안 권장(관계형). 기록·기여 이력 조회에 적합 |
| 스타일 | CSS Modules + CSS 변수(디자인 토큰) | 시안의 질감·번짐 효과를 직접 제어 |
| 애니메이션 | CSS + Framer Motion(부분) | `prefers-reduced-motion`과 앱 내 토글을 함께 지원 |
| 이미지 내보내기 | `html-to-image` (클라이언트) | 서버 렌더링 비용 없음. 폰트 임베드 확인 필요 |
| 테스트 | Vitest(core/server), Playwright(E2E, 다중 브라우저 컨텍스트로 4인 시뮬레이션) | |
| 배포 | 단일 Node 인스턴스(Fly.io 또는 Render) + 관리형 Postgres | 내부 테스트 규모(동시 10팀 이하)는 단일 인스턴스로 충분. 확장 시 Redis adapter 추가 |

## 5. 데이터 모델 (초안)

```
Player        id, deviceToken(hash), nickname, createdAt
Room          id, code(4~6자, 예: 7F2A), hostPlayerId, status, settings(json), createdAt
RoomMember    roomId, playerId, joinedAt, leftAt, role(host|player), isHidden
Game          id, roomId, objectTokenId, attributeTokenId, rerollUsed, phase, round, startedAt, endedAt
GameEvent     id, gameId, seq, type, payload(json), actorId, at        ← 이벤트 로그(재접속·타임라인·지표의 원천)
Contribution  id, gameId, playerId, phase(naming|explore|connect|record), questionId, round,
              text, choiceId(조용한 참여), echoOfContributionId, status(visible|hidden|flagged)
Draft         gameId, playerId, text, updatedAt                        ← 자동 저장
WorldFragment id, worldId, type(rule|place|resident|event|secret), text, sourceContributionIds[]
World         id, gameId, name, serial(예: UMBRELLA 042), coverSeed, visibility(private|members|public), createdAt
WorldMember   worldId, playerId                                        ← 공동 저자
Star          id, worldId, contributionId, fromPlayerId, kind(surprise|connection|afterglow)
Report        id, targetType, targetId, reporterId, reason, status, createdAt
Block         blockerId, blockedId
Token         id, pouch(A|B), label, tags[], active                    ← content 패키지에서 시드
QuestionCard  id, category(use|cost|place|memory|society|change), text, choices[3]
```

- **별은 순위를 만들지 않는다**: 집계 API를 두지 않고, 세계 화면에서 해당 문장의 강조 효과로만 쓴다.
- 성운 배치는 `objectTokenId`로 군집을 만들고(가까운 별) `attributeTokenId`에서 색상을 뽑는다(같은 빛). 클라이언트에서 결정적 해시로 좌표를 계산한다.

## 6. 실시간 프로토콜 (Socket.IO 이벤트)

| 방향 | 이벤트 | 내용 |
|---|---|---|
| C→S | `room:join {code, deviceToken, nickname}` | 입장·재입장 |
| S→C | `room:snapshot {state, you, serverTime}` | 전체 상태(입장·재연결 시, 전이마다) |
| C→S | `game:start` | 방장만 |
| C→S | `pouch:open {pouch}` / `pouch:reroll` | 추첨, 다시 흔들기 |
| C→S | `turn:pickQuestion {questionId}` | 차례인 사람 |
| C→S | `draft:update {text}` | 800ms 디바운스, 자동 저장 |
| C→S | `contribution:submit {text \| choiceId}` | 제출 |
| C→S | `connect:vote {candidateId}` / `record:vote` | 합의 단계 |
| C→S | `star:give {contributionId, kind}` | 별 보내기 |
| C→S | `mod:hide {contributionId}` / `mod:report` | 방장 숨김, 신고 |
| S→C | `toast {kind, message}` | 알림 |

- 모든 C→S 이벤트에 `clientSeq`를 붙여 중복 전송(재연결 직후 재시도)에 멱등하게 처리한다.
- 재접속 시 기기 토큰으로 같은 Player를 복원하고 `Draft`를 되돌려준다. 이것으로 "모바일에서 재접속 가능" 기준을 충족한다.

- 텍스트 대비는 `--text`/`--text-muted`를 `--bg`와 `--surface-2` 위에 둘 때 WCAG AA를 만족하는지 스프린트 0에서 검증한다.

### 8.2 타이포그래피

- 서체: **Noto Sans KR** (Google Fonts, 400/500/700, `font-display: swap`, 한국어 서브셋)
- 시안 기준 크기(16:9 발표 화면): 제목 44 / 본문 20 / 화면 문구 16 → 웹 스케일로 변환:

| 역할 | 모바일 | 데스크톱 |
|---|---|---|
| Display(세계 이름, 홈 카피) | 28px | 44px |
| Title | 20px | 28px |
| Body | 16px | 20px |
| Caption(화면 문구) | 13px | 16px |

### 8.3 질감과 모션

- 배경 이미지 2종은 WebP/AVIF로 변환하고 1x/2x 반응형 이미지로 제공한다(목표: 각 250KB 이하). 텍스트가 놓이는 쪽에 어두운 그라데이션 오버레이를 깐다.
- 천·종이 질감은 이미지 대신 SVG noise 필터와 약한 `backdrop-filter`로 표현한다.
- 모션 원칙: **번짐(blur→focus), 부유(translateY 4~8px, 4~6s), 천천히 열리는 막(clip-path)**. 400~900ms, ease-out.
- `prefers-reduced-motion`이 켜져 있거나 앱 내 "모션 줄이기"를 선택하면 모든 부유·번짐을 opacity 전환으로 대체한다.

## 11. 지표 계측 (기획안 9장)

`GameEvent` 로그에서 배치 쿼리로 계산하며, 대시보드는 MVP에서 SQL 뷰와 CSV 내보내기로 대신한다.

| 지표 | 정의 | 계산 |
|---|---|---|
| 완주율 | 게임을 시작한 방 중 `World` 저장까지 간 비율 | `worlds / games(started)` |
| 기여 균형 | 한 게임 안에서 문장 수·글자 수의 편중 | 플레이어별 글자 수의 **지니 계수**(0에 가까울수록 균형) |
| 연결 행동 | 앞사람 설정을 인용·확장한 문장 비율 | MVP: 직전 라운드 문장과 명사 형태소가 겹치면 후보로 표시하고 운영 테스트에서 수동 라벨로 보정 |
| 재방문 | 14일 이내 다른 조합으로 다시 플레이한 팀 비율 | 같은 멤버 구성(50% 이상 겹침) 기준 |
| 안전 | 신고율, 중도 이탈 시점, 공개 전환 철회율 | 이벤트 집계 |
| 소요 시간 | 단계별 체류 시간 | 15분 완주 검증용 |

관찰용 **테스트 진행 대본**(기획안의 "첫 테스트에서 관찰할 것")은 S5에 운영팀과 함께 작성한다.

## 12. 품질·안전·접근성 체크리스트 (MVP 출시 조건)

- [ ] 중저가 안드로이드 기준 초기 로드 3초 이하(LCP), 번들 200KB(gzip) 이하
- [ ] 외부 공개 빌드에서는 서비스명이 가칭으로 바뀜(설정값 `APP_BRAND`)

### 15.2 계획과 달라진 점

| 항목 | 계획 | 구현 | 이유 |
|---|---|---|---|
| 저장소 | PostgreSQL + Prisma | `.data/` JSON 파일(`FileStore`) | 내부 테스트 규모에서는 설치 없이 바로 돌릴 수 있는 쪽이 낫다. 메서드 단위로 분리해 두어 Postgres 구현으로 바꾸기 쉽다 |
| 무응답 차례 | 30초 뒤 다음 사람에게 질문 선택권 | 30초 뒤 첫 번째 카드로 자동 선택, 방장은 언제든 대신 고를 수 있음 | 선택권을 넘기면 한 라운드가 최대 30초씩 더 늘어난다 |
| 잠깐 끊긴 사람 | 규정 없음 | 20초 동안은 기다리고, 그 뒤 남은 사람만으로 진행 | 모바일에서 화면이 잠깐 꺼지면 라운드가 넘어가 버리는 문제를 통합 테스트에서 발견했다 |
| 확정 방식 | 과반 확정 | 최다 득표 확정(동률은 방장 선택, 그다음 먼저 나온 문장) | 3~4명에서 과반이 안 나오면 진행이 멈춘다 |
| 스타일 | CSS Modules | 디자인 토큰 CSS 변수 + 전역 스타일 한 벌 | 화면 수가 적어 모듈 분리 이득이 작다 |
| 애니메이션 | CSS + Framer Motion | CSS만 사용 | 번들 크기 |
